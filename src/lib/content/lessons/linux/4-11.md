# 进程管理命令

## 什么是进程

**进程**是正在执行的程序的实例。每个进程都有唯一的 **PID（进程 ID）**。

```bash
# 查看进程的基本信息
ps                    # 当前终端下的进程
ps aux                # 查看所有进程（详细）
ps -ef                # 另一种查看所有进程的方式
```

### ps 输出解读

```
USER       PID  %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root         1  0.0  0.1  22564  3840 ?        Ss   Jul25   0:02 /sbin/init
alice     1234  0.5  2.3 524288 47120 ?        Sl   Jul25   1:23 /usr/bin/python3 app.py
```

- **USER**：进程所有者
- **PID**：进程 ID
- **%CPU / %MEM**：CPU/内存使用率
- **STAT**：进程状态（S=睡眠，R=运行，Z=僵尸）
- **COMMAND**：启动进程的命令

## top — 实时监控

`top` 是一个动态的进程查看工具，类似 Windows 任务管理器。

```bash
top                    # 启动 top
top -u alice           # 只看 alice 用户的进程
top -p 1234            # 只看指定 PID
```

### top 交互命令

| 按键 | 功能 |
|------|------|
| `M` | 按内存排序 |
| `P` | 按 CPU 排序 |
| `q` | 退出 |
| `k` | 终止进程（输入 PID） |
| `1` | 显示每个 CPU 核心 |

## htop — 增强版

```bash
htop                   # 启动 htop
# 安装：sudo apt install htop
```

## 终止进程：kill

`kill` 向进程发送信号来终止或控制它。

```bash
kill 1234              # 向 PID 1234 发送 SIGTERM（默认）
kill -9 1234           # 强制终止（SIGKILL）
killall nginx          # 终止所有 nginx 进程
pkill python           # 终止所有包含 python 的进程
```

### 常见信号

| 信号 | 数字 | 用途 |
|------|------|------|
| SIGTERM | 15 | 优雅终止（默认） |
| SIGKILL | 9 | 强制终止 |
| SIGINT | 2 | 中断（同 Ctrl+C） |

```bash
kill -l  # 查看所有信号
```

## 前后台任务管理

```bash
command &              # 后台运行命令
jobs                   # 查看当前终端的后台任务
fg %1                  # 将任务 1 调回前台
bg %1                  # 将暂停的任务放到后台
Ctrl+Z                 # 暂停当前前台任务
Ctrl+C                 # 终止当前前台任务
```

## 实践操作

```bash
# 后台运行
sleep 100 &

# 查看后台任务
jobs

# 调回前台
fg %1

# 后台运行且关闭终端不终止
nohup ./long_task.sh &
```

## 练习任务

1. 使用 `ps aux` 查看所有进程，找到你的用户进程
2. 启动 `top`，按 `M` 按内存排序
3. 后台运行：`sleep 300 &`
4. 用 `jobs` 查看后台任务
5. 用 `fg` 调回前台，然后用 `Ctrl+Z` 暂停
6. 用 `bg` 放到后台
7. 用 `kill` 终止后台任务

## 知识点总结

- `ps aux` 查看所有进程快照，`top`/`htop` 实时监控
- `kill` 向进程发信号，默认 SIGTERM（优雅终止）
- `kill -9` 强制终止，是最后手段
- `jobs`/`fg`/`bg` 管理前后台任务
- `nohup` + `&` 实现后台持久运行

> 💡 提示：kill -9 虽然强大，但不会给进程清理的机会（可能导致数据丢失）。优先使用默认的 SIGTERM。
