# 引用与借用

## 为什么需要引用？

如果每次传递数据都转移所有权，代码会变得非常繁琐。引用允许你**使用值但不获取所有权**。

## 引用（&）

```rust
let s1 = String::from("hello");
let len = calculate_length(&s1);
// s1 仍然有效！

println!("'{}' 的长度是 {}", s1, len);

fn calculate_length(s: &String) -> usize {
    s.len()
}
```

`&s1` 语法创建了一个指向 `s1` 的引用，但不获取所有权。

## 可变引用（&mut）

默认引用不可变，使用 `&mut` 创建可变引用：

```rust
let mut s = String::from("hello");

change(&mut s);

fn change(s: &mut String) {
    s.push_str(", world");
}

println!("{}", s);  // "hello, world"
```

## 借用规则

Rust 编译器强制执行以下规则：

1. **任意数量的不可变引用 `&T` 可以同时存在**
2. **或一个可变引用 `&mut T`**
3. **但不能同时拥有两者**
4. **引用必须始终有效（生命周期）**

```rust
let mut s = String::from("hello");

let r1 = &s;        // OK
let r2 = &s;        // OK
// let r3 = &mut s;  // 错误！有不可变引用时不能可变引用

println!("{} {}", r1, r2);
let r3 = &mut s;    // OK，r1 r2 不再使用
```

## 悬垂引用

Rust 编译器会阻止悬垂引用：

```rust
// fn dangle() -> &String {
//     let s = String::from("hello");
//     &s  // 编译错误！s 离开作用域后被丢弃
// }
```

## 练习任务

1. 编写函数 `calculate_length` 使用不可变引用
2. 编写函数 `append_world` 使用可变引用
3. 尝试同时创建可变和不可变引用，观察编译错误
4. 理解为什么悬垂引用会被编译器阻止

## 知识点总结

- `&T` 不可变引用
- `&mut T` 可变引用
- 可变引用独占：有 `&mut` 时不能有 `&`
- 生命周期确保引用始终有效

> 💡 提示：引用的设计让 Rust 在编译期就能发现数据竞争。这在其他语言中需要运行时检测（如 Go 的 race detector）。
