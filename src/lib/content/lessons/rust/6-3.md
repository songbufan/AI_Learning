# 错误处理

## Rust 的错误处理哲学

Rust **没有异常（exception）**。它将错误分为两类：

| 类型 | 用途 | 处理方式 |
|------|------|----------|
| `Result<T, E>` | 可恢复错误 | 必须显式处理 |
| `panic!` | 不可恢复错误 | 程序崩溃 |

## Result<T, E>

```rust
enum Result<T, E> {
    Ok(T),   // 成功，包含值
    Err(E),  // 失败，包含错误
}
```

### 基本用法

```rust
use std::fs::File;

let f = File::open("hello.txt");

match f {
    Ok(file) => println!("文件打开成功"),
    Err(e) => println!("打开失败: {}", e),
}
```

## ? 运算符

`?` 是错误传播的语法糖，如果值是 `Err`，提前返回：

```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let mut f = File::open(path)?;
    let mut s = String::new();
    f.read_to_string(&mut s)?;
    Ok(s)
}
```

`?` 等价于：

```rust
let mut f = match File::open(path) {
    Ok(f) => f,
    Err(e) => return Err(e),
};
```

## unwrap 和 expect

- `unwrap()`：成功返回 Ok 值，失败 panic
- `expect(msg)`：同 unwrap，但 panic 时显示自定义消息

```rust
let f = File::open("hello.txt").expect("无法打开文件");
```

## panic! 宏

不可恢复错误时使用：

```rust
panic!("发生严重错误！");
```

## 练习任务

1. 用 `match` 处理 `Result<i32, &str>`
2. 用 `?` 重写链式错误传播
3. 实现函数：从文件读取内容或返回默认字符串
4. 对比 `unwrap()` 和 `expect()` 的使用场景

## 知识点总结

- 无异常，用 `Result<T, E>` 处理可恢复错误
- `?` 运算符简化错误传播
- `unwrap()` 只在确定不会失败时使用
- `panic!` 处理不可恢复错误

> 💡 提示：在 Rust 中，编译器会强迫你处理每一个可能的错误。这是 Rust " fearless " 的另一个体现。
