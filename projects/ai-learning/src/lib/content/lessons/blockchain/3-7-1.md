# 智能合约安全漏洞

## 为什么智能合约安全如此重要？

智能合约部署后**不可修改**，代码中的漏洞会导致永久性的资金损失。每年因智能合约漏洞造成的损失高达数十亿美元。

```python
# 智能合约重大安全事故
print("=== 智能合约安全事故 Top 6 ===\n")

incidents = [
    ("The DAO (2016)", "6000万美元", "重入攻击",
     "攻击者利用 withdraw() 的重入漏洞，反复提取资金"),

     "验证节点私钥泄露"),
    ("Poly Network (2021)", "6.1亿美元", "跨链桥攻击",

]

```

## 重入攻击（Reentrancy）

```python
# 重入攻击模拟（The DAO 事件原理）
print("=== 重入攻击原理 ===\n")

print("【有漏洞的合约】")
vulnerable_code = """
contract VulnerableBank {
    mapping(address => uint256) public balances;

    function deposit() public payable {
        balances[msg.sender] += msg.value;
    }

    function withdraw() public {
        uint256 amount = balances[msg.sender];
        require(amount > 0, "余额不足");

        // 漏洞：先转账，再更新余额
        (bool success, ) = msg.sender.call{value: amount}("");
        require(success);

        // 攻击者合约的 fallback 函数可以再次调用 withdraw()
        balances[msg.sender] = 0;  // ← 攻击者已经提取多次了！
    }
}
"""
print(vulnerable_code)

print("【攻击流程】")
steps = [
    "1. 攻击者存入 1 ETH",
    "2. 攻击者调用 withdraw()",
    "3. 合约转账 1 ETH 给攻击者",
    "4. 攻击者合约收到 ETH，触发 fallback()",
    "5. fallback() 再次调用 withdraw()",
    "6. 此时 balances 还没归零 → 再次提取 1 ETH",
    "7. 循环 5-6，直到合约 drained",
]
for step in steps:
    print(f"  {step}")
```

- 重入攻击：外部调用在状态更新前执行
- CEI 模式：Checks → Effects → Interactions（先改状态，再交互）
- 使用经过审计的库（OpenZeppelin）减少风险
