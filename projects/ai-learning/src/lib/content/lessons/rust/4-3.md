# 生命周期

## 什么是生命周期？

生命周期（Lifetime）是 Rust 用来确保所有引用都有效的机制。它不会改变引用的实际存活时间，而是描述引用之间的**关系**。

## 生命周期注解

生命周期注解不会改变引用的存活时间，只是告诉编译器多个引用之间的关系：

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}
```

- `'a` 是生命周期参数
- 表示返回值的生命周期与参数中最短的那个相同

## 生命周期规则

编译器有**三条省略规则**，大多数情况下自动推断：

1. 每个引用参数都有自己的生命周期参数
2. 如果只有一个输入生命周期，它被赋予所有输出生命周期
3. 如果有 `&self` 或 `&mut self`，输出生命周期与 `self` 相同

## 结构体中的生命周期

```rust
struct Excerpt<'a> {
    part: &'a str,
}

fn main() {
    let novel = String::from("Call me Ishmael.");
    let first_sentence = Excerpt {
        part: &novel[..7],
    };
}
```

结构体中的引用必须标注生命周期，确保结构体实例不会比其引用的数据活得更久。

## 静态生命周期

`'static` 是所有生命周期中最长的，整个程序运行期间都存在：

```rust
let s: &'static str = "Hello";
```

所有字符串字面量都有 `'static` 生命周期。

## 练习任务

1. 编写 `longest` 函数并测试
2. 尝试返回两个引用中较短的那个，观察生命周期要求
3. 创建带生命周期的结构体
4. 理解为什么 `'static` 不需要手动标注

## 知识点总结

- 生命周期确保引用始终有效
- 标注语法：`'a`
- 编译器大部分情况自动推断
- 结构体中引用必须标注生命周期
- `'static` 是整个程序的生命周期

> 💡 提示：生命周期是 Rust 中最难的概念之一。记住：它不是运行时检查，是编译期的借用检查。
